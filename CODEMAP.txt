bbq-dashboard — site/static-web 운영 현황판
=========================================

## 구조
- index.html                : 메인 랜딩(통합 현황판 우선 + 업무별 앱 진입 카드, mobile 1열/desktop 2열)
- tests/landing_page_contract.js : 랜딩 semantic navigation·정확한 내부 경로·44px touch target·script/write-free 회귀 검사
- dashboard.html            : 통합 대시보드
- tests/dashboard_news_fallback_test.js : RSS proxy 실패 시 공식 fallback 링크·카드별 재시도·read-only 경계 회귀 검사
- posdelay.html             : PosDelay 운영 대시보드(상태/임계값 표시). 배달료는 Android readback `lastAppliedFee`만 실제값으로 표시하고 null은 `확인 중`, 수동 0원은 0원 그대로 NativeBridge 전달
- tests/posdelay_fee_ui_test.js : Node VM 기반 배달료 확인값/null/0원 회귀 테스트
- kds.html                  : PosKDS 운영 대시보드
- banktotal.html            : BankTotal 운영 대시보드
- evidence.html             : 법적 증빙 페이지
- hikorea-guide.html        : HiKorea 안내
- saaya.html                : SaaYa 페이지
- POSDELAY_UI_STANDARDS.md  : PosDelay UI 카테고리·카드 가이드
- CODEX_HANDOFF.md          : 최근 Codex 전달 메모
- APP_INTENT.md            : 앱/대시보드 목적 및 완료 기준
- AI_HANDOFF.md            : 현재 상태/다음 큐 포인터
- CLAUDE.md                : 세션 운영 규칙
- README.md                : 저장소 문서 개요
- updates/catalog.json     : AppUpdateCenter remote catalog. 퇴역 앱 제외, 최신 미검증 앱의 과거 APK 대체 금지
- updates/<app>/version.json, history.json : GitHub Pages update metadata. AppUpdateCenter index는 사용자용 `.apk`, 내부 updater metadata는 `.bin` Release asset을 가리킨다.
- updates/index.html       : metadata/release 안내 진입점

## 배포
- hosted/public 정적 호스팅(주로 GitHub Pages)로 노출
- 로컬 빌드 불필요
- update metadata는 PR merge 뒤 Pages, APK는 exact rolling Release asset으로 분리 검증

## 주요 의존
- Firebase RTDB Read-only 사용(표시/판독 전용)
- SSE 스트림(실시간 갱신)

## 경계
- `bbq-dashboard`는 site/static-web 기준의 정적 운영 대시보드임.
- `Dashboard(Android WebView)`는 별도 런타임/프로젝트이며 본 저장소와 소유권/동작 경로를 혼동하지 않음.
- Firebase Write, 배포 실행, 카카오/ADB/LIVE action은 별도 승인 범위 또는 별도 작업 흐름으로 분리.

## MCP 정렬
- 검증 체계: Firebase MCP(Read-only), Playwright(스크린샷), Axe(접근성).
- 문서 기준 완료 조건: desktop/mobile 스크린샷 보유, Axe 결과 보유, hosted/public URL 확인, Firebase read-only 경계 확인

## posdelay.html 핵심 영역
- `/posdelay/logs`, `/posdelay/action_log`, `/posdelay/error_reports` 병합 타임라인
- 배달료 게이트: threshold/valid/fee/base 경로의 표시/조정 상태
- 공지/진단: 접힘/펼침 및 활동 로그
